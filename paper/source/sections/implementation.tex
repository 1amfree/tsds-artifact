\section{Implementation}
\label{sec:implementation}

\tool is implemented as a dual-subsystem framework in Python built on angr/claripy~\cite{angr2016} and Z3~\cite{z3solver2008}. The core static evidence engine comprises 524 Python source files (6.82~MB of code), while the accompanying runtime orchestration and discovery subsystem (\textsc{Simulation}) contains 117 files (3.97~MB). Candidate binding, corridor search, matrix policy, projection, provenance, refinement, and standalone auditing are strictly modularized. The shell-vector matrix maintains a stable schema and SHA-256 identity; changing any token, quote context, or syntax template creates a distinct, content-addressed evidence domain.

The evaluator supports 32-bit ARM/MIPS ELF binaries, imported and vendor-wrapped sinks, delay slots, position-independent calls, and common firmware runtime libraries. A command is admitted as complete only upon encountering a verified NUL terminator within its declared buffer bounds. String append summaries first locate an observed destination terminator and then materialize the bounded append; when that boundary is indeterminate, the evaluator avoids heuristic offset guessing and emits an explicit typed obligation. A Latin-1 projection displays byte offsets without lossy Unicode or locale normalization to preserve unsummarized decoders and multibyte transformations for human audit. Direct \texttt{system}/\texttt{popen} bindings strictly follow their ABIs, whereas vendor wrappers require a rendered-format registration keyed by binary digest, address, and argument contract. Deterministic memory concretization isolates unconstrained storage across parallel workers.

For cloud-scale batch processing across firmware archives, the architecture incorporates five specialized modules: (1)~\emph{Binary slot provenance} isolates direct propagation from reconstructed fillers; (2)~\emph{Closure identity and deadlines} tracks timeouts by content digest; (3)~\emph{Multi-level caching} accelerates persistent callsite reuse across firmware variants; (4)~\emph{Static-dynamic reconciliation} correlates corridors with runtime listener evidence; and (5)~\emph{Tool-assisted review} supports zero-execution schema auditing.

To support horizontal scaling in cloud DevSecOps pipelines, each closure executes within an isolated worker process. A POSIX forkserver preloads immutable binary contexts to maximize memory sharing; workers enforce strict resource limits aligned with cloud batch containers: 45~s for the engine, 90~s after initialization, a 150-s outer envelope, 500 steps, an 8-GiB address-space limit, 20/60/120 active-state caps, four escape states, and a 2,048-entry projection cache.

The append-only JSONL ledger binds candidate/binary identities, sink metadata, command projection, controlled offsets, provenance, matrix decisions and witnesses, projection digests, scheduler state, conditioning, and residual obligations. A contract-focused Linux receipt (Python 3.10.12) records \TSDSReviewContractTests{} passing checks, \TSDSReviewContractWarnings{} warnings, and \TSDSReviewContractSubtests{} passing subtests, with zero sanitizer-test exclusions. Separately, reference/replay and cache comparisons over \TSDSReviewStrictTargets{} R7000 analysis targets report zero recursive semantic differences. These receipts support repeatability of the recorded interfaces; they are not an independent semantic oracle or a firmware-wide correctness proof.
